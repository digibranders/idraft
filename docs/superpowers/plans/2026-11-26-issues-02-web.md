# Issues page, web: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Issues page of the real app at `/{workspace}/{project}/seo/issues`: the list of checks in two
tabs, one open check with its pages, the states, and the sidebar group "Website audit".

**Architecture:** Pure logic (address state, row order, texts per check) lives in `src/lib/issues/`. The screen
lives in `src/features/internal-links/issues/`, inside the feature that owns the crawl, because the lint rules
forbid one feature importing another and the screen reuses that feature's crawl states, crawl reads, "Crawl now"
button and page inspector. The API returns ids; every visible word is in `messages/en.json`. Spec:
`docs/superpowers/specs/2026-11-26-issues-page-design.md` (sections 5 to 8, 11 and 12). The backend plan
(`2026-11-26-issues-01-backend.md`) is built first.

**Tech stack:** Next.js (App Router), React, TypeScript, TanStack Query, nuqs, next-intl, Tailwind v4 tokens,
vitest with Testing Library, pnpm.

```ts
export type IssuesTab = 'technical' | 'on-page';
export type IssuesSeverity = 'all' | 'error' | 'warning' | 'notice';
export type IssuesFoundBy = 'all' | 'crawl' | 'ranks' | 'gsc' | 'ai';
export interface IssuesState {
  tab: IssuesTab;
  check: CheckId | null;
  severity: IssuesSeverity;
  by: IssuesFoundBy;
  q: string;
  showPassed: boolean;
  sort: string | null;
}
```

  argument for this).

- [ ] **Step 6: Words.** Add the namespace `issues` to `messages/en.json`. Check names, "why" and "fix":

| id | name | why | fix |
|---|---|---|---|
| `status-4xx` | Pages that return a 4xx error | Visitors and Google get an error instead of the page, and every link to it is wasted. | Restore the page, redirect its address to the closest live page, or remove the links to it. |
| `status-5xx` | Pages that return a 5xx error | The server failed to answer. Google crawls a site less often when this repeats. | Check the server logs for these addresses and fix the cause. |
| `clicks-page-broken` | Broken or redirected pages with Google clicks | People click the result in Google and land on an error or on another page. The clicks stop once Google drops the address. | Restore the page, or redirect its address to the page that answers the same search. |
| `rank-page-broken` | Broken or redirected pages that rank for a keyword | The keyword still ranks with an address that no longer answers with the page, so the rank will be lost. | Restore the page, or redirect its address to the page you want to rank for the keyword. |
| `cited-page-broken` | Broken or redirected pages cited in AI answers | An AI answer sends people to an address that no longer shows the page it cited. | Restore the page at the cited address, or redirect it to the page with the same content. |
| `clicks-page-orphan` | Orphan pages with Google clicks | The page earns clicks with no help from the rest of the site. Internal links would make it stronger. | Link to the page from related pages, starting with the ones that get the most visits. |
| `redirect-broken` | Redirects to a broken page | The redirect sends visitors and Google to an error. | Point the redirect at a live page. |
| `redirect-chain` | Redirect chains | Each extra hop slows the visit, and Google may stop following a long chain. | Point the first address straight at the final page. |
| `links-to-redirect` | Pages that link to a redirect | The link works, but every click and every crawl takes an extra hop. | Change the link to the final address. |
| `redirect-pages` | Addresses that redirect | Not a problem by itself. Listed so you can check that each redirect is intended. | Keep the ones you set on purpose, and remove internal links to them. |
| `canonical-broken` | Canonical points to a broken or redirected page | Google is asked to index an address that does not answer with a page, so it may index neither. | Set the canonical to a live page that returns 200. |
| `noindex` | Pages set to noindex | Google is told to keep these pages out of its index. | Remove the noindex tag if the page should be found in Google. |
| `canonical-elsewhere` | Canonical points to another page | Google is asked to index the other page instead of this one. | Check that each one is intended, and link to the canonical page instead of this one. |
| `sitemap-broken` | Sitemap lists an address that does not return 200 | The sitemap should only list pages you want indexed. Errors and redirects in it waste crawling. | Remove the address from the sitemap, or list the final live address. |
| `sitemap-nonindexable` | Sitemap lists a page that is not indexable | The sitemap asks Google to index a page that the page itself asks Google to leave out. | Remove the page from the sitemap, or make it indexable. |
| `not-in-sitemap` | Indexable pages missing from the sitemap | Google can still find them through links, but new and changed pages are picked up more slowly. | Add the pages you want indexed to the sitemap. |
| `broken-internal-links` | Pages with broken internal links | A visitor who clicks lands on an error, and the link passes nothing on. | Change each link to a live page, or remove it. |
| `orphans` | Orphan pages | No page on the site links to it, so visitors cannot reach it and Google finds it only through the sitemap. | Link to the page from a related page, or remove it if it is not needed. |
| `editorial-orphans` | Pages with no editorial links in | The page is linked only from menus, footers or automatic blocks, which tell Google little about it. | Add a link in the text of a related page. |
| `links-to-nonindexable` | Pages that link to a non-indexable page | The link leads to a page Google is asked to leave out of its index. | Link to the indexable version of the page. |
| `deep-pages` | Pages more than 3 clicks from the home page | Pages far from the home page are crawled less often and get fewer visits. | Link to the page from a page closer to the home page. |
| `nofollow-internal` | Pages with nofollow internal links | A nofollow link between your pages tells Google not to follow it. | Remove nofollow from links between your pages. |
| `title-missing` | Pages without a title | The title is the line people see in Google. Without one, Google writes its own. | Give each page a title that says what it is about. |
| `title-duplicate` | Pages that share a title | Google cannot tell the pages apart from their titles, and neither can a searcher. | Write a title for each page that says what is different about it. |
| `title-long` | Titles over 60 characters | Google cuts long titles off, so the end may not show. | Put the main words first and keep the title short. |
| `title-short` | Titles under 30 characters | A very short title says little about the page and leaves room unused in Google. | Add what the page offers and who it is for. |
| `url-format` | Addresses with capitals or underscores | Addresses are easier to read, type and share in lower case with hyphens. | Use lower case and hyphens for new pages. Change an old address only with a redirect. |
| `url-long` | Addresses over 115 characters | Long addresses are cut off in Google and are hard to share. | Use shorter addresses for new pages. |
| `off-target` | Target pages that another page of yours outranks | You set this page as the target of a keyword, and Google ranks another page of yours for it. | Make the target page the better answer, and link to it from the page that ranks. |
