## 3. Design

- Statistics (T1): `maintenance.py` holds `AI_ANALYZE_TABLES` and `async def analyze_ai_tables(connection: asyncpg.Connection) -> int` (returns the number of relations analyzed). One statement per table: `ANALYZE <table>`; table names come from the constant, never from input. `analyze.py` is `main()` like `migrate.py`: loads the migrator settings, connects, calls the helper, logs. `migrate.main()` adds the call after `upgrade_to_head`, inside `try/except Exception` that logs `analyze skipped` and goes on.
- Gate (T2): `BT/api/ai/plan_support.py`: `captured_plans(resources, pg, call)` runs `call` once under `statements`-like recording of (statement, parameters), then replays each SELECT on the superuser connection as `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) <statement>` with its parameters, inside one transaction, after `SET LOCAL enable_nestloop = off` when a `SET LOCAL enable_nestloop` statement preceded it in the captured log (so the gate sees what the service sees); `rows_visited(plan)`, `worst_node(plan)`, `forget_statistics(pg, tables)`, `autovacuum_off(pg, tables)` (context manager). `BT/api/ai/test_explain_gate.py`: `READS` matrix: summary plain, `include=series,entities`, `include=co_mentions` with twenty entities (helper `_twenty_entities` and `_name_all` of `test_summary_comentions.py` imported), `compare=previous_period`, sources `domains`, `pages`, `changes`, `diversity`, `prompts`, `fanout`, `citations`, a `domains/{registrable_domain}` detail, the Overview and `overview/ai`, `ai.citation_share`, the series and the breakdown by topic, competitors with `include=lost_prompts,top_sources`, `overview/competitors`. Each read is called with the params of its own test module's helpers (`get_overview`, `get_metric`, `full.url("ai","sources",...)`), window 28 days.
- Counters (T3): `B/ai/quality.py`: `QualityResult` (frozen dataclass: `check`, `workspace_id`, `project_id`, `engine_code`, `n`, `value`, `baseline`, `threshold`, `state`), `CHECKS` (name, minimum n, threshold, doc reference), `async def ai_quality_checks(connection, day) -> list[QualityResult]`. One grouped statement per check over `ai.observations` with `observed_at` bounds for the day and for the 7 day baseline (`observed_date` bounds make the partitions do the work), grouped by `(workspace_id, project_id, engine_code)`; the statement count is constant (5 checks, 5 statements) whatever the number of projects. Checks (doc 25 section 9, `rule_version = 1` constant):

| Check | Value | Flag when | Minimum n |
|---|---|---|---|
| `ai_status_mix` | `error + empty` share; `refused` share | `error + empty` > 10%, or `refused` > 2 x its 7 day baseline | 100 per engine |
| `ai_citation_presence` | valid answers (`complete`, `partial`) with `has_citations` | below 70% of the 7 day baseline | 200 |
| `ai_fanout_presence` | valid `chatgpt_web` answers with `fanout_count > 0` | below 50% of the baseline | 100 |
| `ai_model_change` | a `(engine_code, model_reported)` first seen on `day` and not before | any | 1 |
| `ai_duplicate_answers` | replicate groups `(collection_run_id, prompt_version_id, engine_code)` with a repeated `answer_hash`, over groups of two or more | > 50% | 50 groups |

  The baseline is the 7 UTC days before `day`; an empty baseline gives `insufficient_data`. Excluded here on purpose: the checks that need in-memory counters (schema mismatch, uncertain mentions, redirect and rank counters), the AI Overview presence check (rank side), and `ai_collection_degraded` (a per run valid rate: WP-30's coverage route).
- Capacity probe (T4): `BT/perf/capacity.py` builds the trigger world with the same SQL shape as `full_project` but 150 prompts x 3 engines x one answer per day for 92 days (41,400 answers, 10 citations each), no `ANALYZE`; `BT/perf/test_ai_read_budgets.py` is skipped unless `IDRAFT_PERF=1` (a `pytest.mark.skipif`, no new marker, `--strict-markers` stays green) and times each class of doc 16 13.4 five times warm, printing a table and asserting p95 under `BUDGETS_MS`: summary 800 (D-33), Overview 300 x 2 (the 300 ms of doc 16 is the V1 host with caching and rollups; the probe asserts twice that, as WP-32's numbers are 160 to 311), sources domains 800, competitors 500. The constants live in the test with the doc reference.
