## What the real code changed against the outline

- The Links tab is `links/links-tab.tsx` (`LinksTab` guards, `LinksList` reads) with `links/edge-columns.tsx` and the shared `ScopeMenu`. The columns are `DataTableColumn`s; a column takes `headerTooltip`.
- `EdgeRow` has no added or new flag (checked in `schema.ts`). The Added mark therefore comes from one read of `changes/links?change=added&link_scope=all&only=all&limit=200`, matched by `source>target`. That list is capped, so the column header says so when the answer has more rows than were read ("Marked for the first 200 of N added links"), and a link not in the list shows nothing, never "not added". A failed read says so in the header tooltip.
- The Changes tab already holds the Lost table: `changes/change-links-panel.tsx` (offset paging, priority tone, export footer, `LinksDropped` on 410, `truncated` and paging limit notes). It is reused as is for the Lost view. It gets one optional prop `listOnly` (the crawl date): no Lost and Added switch, no scope menu, no tier switch, and a "Lost on" column. `links/lost-links-table.tsx` is the thin wrapper that maps the Links scope to a changes scope (editorial stays editorial, every other scope reads all) and gives the date. `readLinks` in the panel is exported as `readChangeLinks`.
- Whether the crawl has an earlier crawl to compare comes from `changesSummaryQuery`: `ready` and `pending` compare, `first_crawl` and `unavailable` do not (the Status menu, the Added column and the Lost view are hidden, and an address `ls` reads as Active). Whether the earlier crawl kept its links comes from `crawlsQuery` (`previous_run_id` of the summary, `links_available` of that crawl); the Lost view then says so with the existing `changes.previousDropped` text instead of an empty list. `links/link-comparison.ts` holds both reads.
- `ls` joins `url-state.ts` (`linkStatus`, allow-list `active | lost | all`).
- The export menu and the in-flight guard live in `crawl-header.tsx` and `internal-links-screen.tsx`. The summary gets its own entry in the same menu (and in More below `md`), its own guard, and a hook `export/use-client-summary.ts`.
- `clientSummaryHtml` (Task 11) is kept. Four small additions: `crawlLine` gets the page count as a number (so the catalog can use a plural), `olderNote` words and `older` input, `lost: null` with words `lostUnavailable(reason)` for a crawl whose links are not stored or that has no comparison, and `lostTotal` so "Plus N more" counts the links the API holds beyond the 200 read.
- There is no `downloadHtml` in the repo. `lib/api/download.ts` gets one small helper over `downloadBlob`.
- Lost links read 410 for a crawl whose links were dropped: the summary is built without that section and says so; it never fails the export.
