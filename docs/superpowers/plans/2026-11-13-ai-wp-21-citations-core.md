## 1. House rules in force for every implementer

- One fresh Sonnet subagent per task (Haiku only for message strings, mock data tables and test boilerplate; never Opus), one subagent at a time. A fresh Sonnet reviewer reads the task, this plan and the diff after every task, runs the task's targeted tests, checks these rules and returns PASS or a numbered fix list; the implementer fixes and the reviewer checks again.
- **UI work rule.** Every task that writes markup, styles or components (T2b, T2c, T3a, T3b, T4a, T4b, T5a, T5b, T5c) invokes `Skill(skill="design-taste-frontend")` BEFORE the first file is written. The repo's own `DESIGN_SYSTEM.md`, `AI_DEVELOPMENT_UI_RULES.md` and `docs/design-system/` outrank the skill's generic opinions: fonts, tokens, radii, spacing and patterns follow the project; take the skill's anti-slop discipline and leave its house style at the door. Reuse before building; never invent a visual pattern.
- Tests first, red for the right reason, then code, green, then checks, then ONE commit `WP-21: <task title>` naming only the task's files (T1 makes three, T2 three, T3 two, T4 two, T5 three). No attribution lines. Never stage another session's files. Edit files with the file tools only (no heredocs, `sed` or replace scripts). If a tool leaves an untracked `apps/web/AGENTS.md` or `apps/web/CLAUDE.md`, delete those two files before the full suites and after the build; `git status` must show neither.
- Tokens only (no hex, rgb, hsl, oklch, no palette classes, no arbitrary values); the 15 `type-*` utilities only, `num` on every compared number; spacing steps 0, 0.5, 1, 1.5, 2, 3, 4, 5, 6, 8, 10, 12; sizes `h-control`, `h-control-sm`, `h-row`, `h-row-compact`; inspector tables are always compact rows. Numbers and dates only through `@/lib/format` (`formatInteger`, `formatPercent`, `formatPointsDelta`, `formatTableDateTime`, `formatDetailDateTime`, `formatRelative`, `formatList`, `displayUrl`, `EMPTY_VALUE`); no `Intl`, `toFixed`, `toLocaleString`, date-fns `format` in components. Lucide icons through `Icon`. No `any`; explicit return types; no non-null assertions.
- Honest numbers: every share shows "of N units" (visible text next to the table or the cell, plus the cell's tooltip and description); a position says "Source 2 of 9", never rank, never "#2"; unknown is never zero ("n/a" with a reason, "No answers", "None named" in words); engines are never pooled silently (a sum over engines says "all engines" and the engines stay listed; an average says "avg of N engines"); colour only for a detectable change, and no detectability test exists for a source share, so every change of a share is neutral (`isDetectable: null`); no composite score; a percent always shows its count.
- Copy: every visible string is a key in `W/messages/en.json` (sections 5), sentence case, ASCII, no em-dash or en-dash anywhere (code, comments, tests, commit messages included; ranges say "to"), no exclamation mark, no straight double quotes inside a message, "cannot" in full. A string is never built by joining parts in code: ICU messages, `formatList` and `@/lib/format` do that. Files are ASCII: `grep -nP '[^\x00-\x7F]' <files>` prints nothing (the typographic minus comes only from `@/lib/format`).
- Both themes, both densities, four widths, on every new surface: loading (skeleton, no full-page spinner, pulse not shimmer), empty (reason and action), error (`InlineError` with Retry; other content stays), partial, stale, refetch (previous data kept at full opacity; the table's static 2 px bar where the part has one). Motion 100 to 200 ms, only for state changes.
- State in the URL: tab, filters, sort, min support, compare, density, columns, inspector. Provider text (titles, hosts, raw URLs) is data: React text only, never markup, never a link unless `webHref` accepts it (`URLCell` does this).
- Checks, from `apps/web`, per task (replace `<files>` with the task's source and test files):
  - light (no lock): `pnpm exec eslint --max-warnings 0 <files>` and `pnpm exec prettier --check <files>`.
  - targeted tests: `infra/dev/heavy --lane medium --label wp21-tN-test -- bash -c 'cd apps/web && pnpm exec vitest run <paths> --maxWorkers=2'`.
  - once at the end of a task: `infra/dev/heavy --lane medium --label wp21-tN-types -- bash -c 'cd apps/web && pnpm typecheck'`.
  - Full `pnpm test`, `pnpm build` and `playwright` run ONLY in T8 (and the e2e spec in T6 through the heavy lane), and only when the first line of `/tmp/idraft-health/state` is `level=OK` (read it again before each run), with `--maxWorkers=3` for vitest.
  - After any edit in `S/features/prompts` the folder runs: `pnpm exec vitest run src/features/prompts --maxWorkers=2` (medium lane).
- No dev server except for a task's browser check, on port 3007 with `NEXT_PUBLIC_API_MOCKING=all`, stopped after (the built-in browser pane cannot register the MSW worker: headless Playwright only). Never kill a process to free a port.

## 4. Data model and reads

Types are `Schemas['SourceDomainRow']`, `SourcePageRow`, `SourcesMeta`, `SourceDomainPage`, `SourcePagePage`, `CitationRow`, `CitationPage`, `SourceChangePage`, `SourceChangeRow`, `SourceDiversity`, `SourceDiversityEngine`, `PromptOwnPagesPage`, `PromptOwnPagesRow`, `MetricCell`, `EngineUnits`, `RoleUnits`, `EngineRoleUnits`, `CitedWith`, `SourceWeekUnits`, `SourcesWeek`, aliased in `L/types.ts` (`DomainRole`, `EngineCode` from `@/lib/api/types`).

`SourceFilters` (what every read shares): `from`, `to`, `engines` (at most 3 codes), `promptId?`, `term?`, `roles?`, `includeBranded`. `filterParams(filters)` maps them to `from`, `to`, `filter[engine_code_in]`, `filter[prompt_id]`, `filter[term]`, `filter[domain_role_in]`, `include_branded`; empty or default values are left out (so the key equals the URL).
