# Entities, Domains, Locations and Taxonomy (Frontend) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a team tell the product who it is and who it competes with: the own brand, its domains and aliases, up to 10 competitors, the project's primary domain and location, and the taxonomy that keywords and prompts are filed under. The alias test shows today what extraction will count.

**Architecture:** The screens of build-order step 4 (docs/29 section 1.1, Phase 2) on top of the workspace setup plan (`docs/superpowers/plans/2026-10-01-workspace-setup.md`, merged on 2026-10-01). Three project settings sections join `SettingsFrame` (Entities and aliases, Domains, Taxonomy); an entity editor page sits under Entities; the new-project form and Project settings > General gain the primary domain and the default location, and the new-project form the own brand. The backend builds the routes on `backend/entities` (its plan `docs/superpowers/plans/2026-10-01-entities-taxonomy.md`); this plan builds the parts that need no generated types first and each screen once its routes are in `backend/openapi/v1.json`.

**Tech Stack:** As the foundation: Next.js 16.3, React 19.3, TypeScript 6 strict, Tailwind 4.3, Base UI 1.8, TanStack Query 5, react-hook-form 7 with zod 4, next-intl, openapi-fetch, MSW 2, Vitest 5, Playwright 1.63.

### Task 1: Primitives

**Files:** `src/components/ui/{tag,textarea,multi-select}.tsx` with tests; `src/components/app/forms/domain-input.tsx` with test; `src/lib/domains/normalize.ts` with test; `src/components/design-system/` sections and `section-slugs.ts`.

- [x] **Step 1:** `normalizeDomain(raw)` returns `{ ok: true, domain, ignoredPath }` or `{ ok: false, code: 'empty' | 'spaces' | 'scheme' | 'host' | 'private' }`: adds a scheme, lower-cases, drops `www.`, a trailing dot, the port, path, query and fragment; refuses IPs and `localhost`; converts to punycode through the URL parser. It is a preview only: the API canonicalizes (doc 14 section 3) and its answer wins. Tests first, from doc 14's host vectors (`Acme.COM.`, `https://www.acme.com/x`).
- [x] **Step 2:** `Tag`, `Textarea` (3 to 8 lines, counter), `MultiSelect` (chips; creatable; Backspace removes the last chip; "Remove {value}") to the inventory contracts, each with axe and keyboard tests.
- [x] **Step 3:** `DomainInput` renders the preview line ("Will track: hubspot.com (path /products/crm ignored)") and the section 12 messages; attributes as section 12's table.
- [x] **Step 4:** Design-system sections for the four, e2e section check, gates, Opus review, commit "Add tag, textarea, multi-select and domain input".

As built: `normalizeDomain` also returns `display`, the host in the letters it was typed in, and decodes the dropped path for reading. `MultiSelect` lists only values that are not chosen (Enter never removes one), puts the add row first, keeps the list open after a pick, and keeps typed text as a value when focus leaves the field. `Textarea` grows with `field-sizing` and with a scroll-height fallback elsewhere. Deviations are rows 117 to 120 of the component inventory.
