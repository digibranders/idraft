## 3. Risks

1. **WB-PRM-18 cannot be wired by this package.** Wiring needs (a) `'cells'` in the `include` type of `summaryQuery` (`prompt-queries.ts`), (b) `'cells'` in the `SERIES` constant of `prompts-screen.tsx` (forbidden file), (c) the two seam lines in `seams/columns.ts`, and (d) the summary mock to serve `include=cells` (it rejects it today, and a test pins that). T6 ships the column, its cell model and tests with fixture rows, leaves the seam lines commented, and writes a hand-over note (exact edits, in T6 and in the As built note). The row stays PARTIAL in the report.
2. **Home of the project wide view.** The brief owns `features/fanout/`, which the lint boundaries make unusable (F11). The plan puts the tab in `features/citations/fanout/` and needs six leases on Citations files. If the coordinator prefers a page of its own, it needs a `NavKey`, a registry entry, a route file and sidebar test changes, which is more than this package may touch: say so before T5.
3. **"New in window" is not in the API** (F6). The plan reads the period before the window (same length, `min_support=1`, 200 rows) and calls a query new only when the whole period before is in hand and has answers; otherwise it says why it cannot tell, and shows no badge. A backend field (for example `first_seen_before_window`) would remove the second read; listed in the report asks.
4. **Tab count changes break tests outside the package** (F9): handled by explicit leases in T4; the mobile e2e is the one that needs a real browser to confirm four tabs still fit.
5. **The mean queries per answer (F2) cannot be read from the route** (F7): the tab shows presence (F1) only; the mean exists per prompt in the summary (F12) and arrives with the column.
6. **Payload and reads.** A fan-out read is up to 200 rows with 5 cited domains each (a few hundred KB). The tab makes at most three reads (current, previous for the badge, and a topics read only on the By topic view), each with `staleTime` of 5 minutes and no focus refetch; the previous read is `enabled` only while the Queries view shows rows. The inspector asks 10 rows, then 50, 100, 200 on "Show more".
7. **The mock lacks `engine_has_no_fanout`** (F3): the guard is a request-log test, not the mock.
8. **Cut answers lose queries silently.** `answers_truncated` counts answers, not queries; the note says "some queries are missing" and never a number of queries.
9. **No design preview** for fan-out (F15): the layout follows 23 4.1 and 24 9.7; the browser pass in T7 is the first time it is seen.

## 5. House rules for every task

- One fresh Sonnet subagent per task (Haiku only for message strings and test boilerplate), a fresh Sonnet reviewer after each task (the brief's Review section), tests first, red for the right reason, then code. Edit files with the file tools only: no shell heredocs, `sed` or replace scripts. Never stage the generated `apps/web/AGENTS.md` or `apps/web/CLAUDE.md`.
- **UI rule.** Any task that writes markup, styles or components (T2, T3, T4, T5, T6) invokes `Skill(skill="design-taste-frontend")` before the first file. `DESIGN_SYSTEM.md`, `AI_DEVELOPMENT_UI_RULES.md` and `docs/design-system/` outrank the skill's own style.
- Design tokens only (no hex, rgb, hsl, no palette classes, no arbitrary values); the `type-*` utilities only, `num` on every compared number; spacing steps and sizes as the neighbours use them. No pie, no gradient, no decoration. Colour only for a detectable change: no fan-out figure has a test of change, so every badge is neutral (outline).
