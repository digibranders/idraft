## 1. House rules in force for every implementer

- One fresh Sonnet subagent per task (Haiku only for message strings and test boilerplate; never Opus), one subagent at a time. A fresh Sonnet reviewer reads the task, this plan and the diff after every task, runs the task's targeted tests, checks these rules and returns PASS or a numbered fix list; the implementer fixes and the reviewer checks again. Review fixes are a commit `WP-19: review fixes of <task>`.
- **Prove it bites** (MASTER-PLAN section 5, the detectability rule is a guard): the reviewer of T1a, T2a and T4a weakens `rateChange` (always `true`, then `detectable !== false`, then ignoring the sign guard) in a scratch commit that is never pushed, runs the task's targeted tests, records the failing test names in the report, and restores the guard.
- **UI work rule.** Every task that writes markup, styles or components (T1c, T2a, T2b, T3a, T3b) invokes `Skill(skill="design-taste-frontend")` BEFORE the first file is written. The repo's `DESIGN_SYSTEM.md`, `AI_DEVELOPMENT_UI_RULES.md` and `docs/design-system/` outrank the skill's generic opinions; reuse before building; never invent a visual pattern.
- Tests first, red for the right reason, then code, green, then checks, then ONE commit `WP-19: <task title>` naming only the task's files. No attribution lines, no dashes. Never stage another session's files. Edit files with the file tools only (no heredocs, `sed` or replace scripts). If a tool leaves an untracked `apps/web/AGENTS.md` or `apps/web/CLAUDE.md`, delete those two files before the full suites and after the build; `git status` must show neither.
- Tokens only; the 15 `type-*` utilities only, `num` on every compared number; spacing steps 0, 0.5, 1, 1.5, 2, 3, 4, 5, 6, 8, 10, 12; sizes `h-control`, `h-control-sm`, `h-row`, `h-row-compact`; inspector tables are compact rows. Numbers and dates only through `@/lib/format` (`formatPercent`, `formatPointsDelta`, `formatSampleCount`, `formatDateRange`, `formatList`, `EMPTY_VALUE`); no `Intl`, `toFixed`, `toLocaleString`, date-fns `format` in components. Lucide icons through `Icon`. No `any`; explicit return types; no non-null assertions.
- **Honest numbers.** A change is in points (`+5.3 pts`), never a relative percent. Every change has its previous value and counts in the tooltip ("Previous 29%, 7 of 24 answers"). Colour only when the change is detectable: `isDetectable === true`, and only `Delta` and `DeltaCell` pick the tone; no file of this package names a green or red class (T4a scans for it). A change with no test (share of voice, a count too small, a sign disagreement) is `isDetectable: null`, neutral, with the reason in words. A delta that is tested and not larger than normal variation says "within normal variation". Every delta carries `test="interim"` until the API sends `is_detectable`. Unknown is never zero: no previous means nothing is drawn in a chip or beside a percent, `n/a` with a reason in a change column; a rate under 4 valid answers has no change. Engines are never pooled silently: an average of engines says how many took part, and a test on pooled answers says "pooled" in its tooltip. No composite score.
- Copy: every visible string is a key in `W/messages/en.json` under `prompts.compare` (section 5), sentence case, ASCII, no em-dash or en-dash anywhere (code, comments, tests, commit messages included; ranges say "to"), no exclamation mark, no straight double quotes inside a message, "cannot" in full. A string is never built by joining parts in code: ICU messages, `formatList` and `@/lib/format` do that. Files are ASCII: `grep -nP '[^\x00-\x7F]' <files>` prints nothing.
- Every new surface has loading (skeleton; no full page spinner), empty (reason and action), error (`InlineError` with Retry; other content stays), partial, stale and refetch (previous data kept at full opacity; `aria-busy`). A failed REFETCH (data held, the new read failed) is told from a failed first read by `isError && data === undefined`, as `summaryFailed` does; the first keeps the table and shows the summary banner with Retry, the second the error state with the error id (`useErrorId`, never the HTTP status as text). Reads wait for the engines (`enabled.length > 0`). Motion 100 to 200 ms, only for state changes.
- State in the URL (`cmp`, `detectable`), written with history replace; the default of each key writes nothing. Compare is scope: Clear filters leaves it.
- Checks, from `apps/web`, per task (replace `<files>` with the task's source and test files):
  - light (no lock): `pnpm exec eslint --max-warnings 0 <files>` and `pnpm exec prettier --check <files>`.
  - targeted tests: `infra/dev/heavy --lane medium --label wp19-tN-test -- bash -c 'cd apps/web && pnpm exec vitest run <paths> --maxWorkers=2'`.
  - once at the end of a task: `infra/dev/heavy --lane medium --label wp19-tN-types -- bash -c 'cd apps/web && pnpm typecheck'`.
  - after any edit under `P`: `pnpm exec vitest run src/features/prompts src/mocks src/lib --maxWorkers=2` (medium lane).
  - Full `pnpm test`, `pnpm build` and Playwright run ONLY in T4b (the e2e spec) and T5, through `infra/dev/heavy` and only when the gate holds: `infra/dev/heavy --status` prints `pause: off`, the first line of `/tmp/idraft-health/state` is `level=OK`, memory free is at least 40 percent, load5 is at most 14 (read them again before each run), and vitest runs with `--maxWorkers=3`. ## 4. Data model and reads

One read, `summaryQuery` in `P/prompt-queries.ts`, with a new field in `SummaryScope`:
`compare?: boolean` adds `compare: 'previous_period'` to the query when true. Everything else is unchanged (`from`, `to`, `include_branded`, `filter[country_iso]`, `branded_only`, `include=series`). Types are `Schemas['PromptsSummary']`, `PromptSummaryRow`, `TopicSummaryRow`, `EngineSummary`, `EngineCells`, `MetricCell`, `MetricWindow` (all in `S/lib/api/types.ts` or `Schemas[...]`).

`L/compare-model.ts` (pure): `parseCompare`, `cmpParam`, `compareParams`, `isCompared`, `comparedWindow` (D8).

`L/change-model.ts` (pure):
```ts
interface Side { value: number; answers: number; successes: number | null; prompts: number | null }
interface RateChange { points: number; detectable: boolean | null; now: Side; before: Side; engines: number }
rateChange(now: RateReading, before: RateReading, metric: CellMetric): RateChange | null
engineChangeOf(cells: readonly EngineSummary[] | undefined, code: string, metric: CellMetric): RateChange | null
averageChangeOf(cells: readonly EngineSummary[] | undefined, codes: readonly string[], metric: CellMetric): RateChange | null
stripChangeOf(prompts: readonly StripPrompt[], code: string, metric: CellMetric): RateChange | null
deltaInput(change: RateChange | null): MetricDeltaInput   // value null when change is null; unit 'points'; polarity 'higher_is_better'
```

### Decisions that changed on the way

- **Q11, no fixture edit.** The plan said to leave the fixtures alone and assert the rule on whatever the mock draws. At 28 days the Fynix mock has no detectable Mention change at all, so the e2e could not see a coloured delta. A cookie, `mock-compare-detectable` (`COMPARE_DETECTABLE_COOKIE` in `mocks/session.ts`, lease taken in tracker commit `42a3db8b`), makes the summary mock flip the mentions of one topic in the compared window only (`withDetectableChange` in `mocks/handlers/compare.ts`): Paid Search and its two prompts, same answers, opposite mentions, +58.3 pts on the topic. Without the cookie the answer is unchanged. Nothing in the app writes the cookie.
- **R10, the seam context grew.** The plan left `PromptColumnContext` alone and had the cell read `useCompare()`. A `cellTip` is a pure function, and the Prompts columns are built above the page's provider, so the context gained `compare`, `comparedWindow` and `changeWords`, and `ComparedWindowProvider` plus an optional window argument of `usePromptColumns` and `useRateColumns` were added. `seams/columns.test.ts` follows. `cellsOfPrompt` moved from `prompt-columns.tsx` to `prompt-model.ts` so the new column file can import it without a cycle.
- **D10, `DeltaValue`, not `DeltaCell`.** A change cell draws `DeltaValue` inside a `col.volumeTrend` cell. `DeltaCell` pushes its value to the right edge, and the column API has no header alignment, so a `DeltaCell` sits far from its left aligned header. The Citations tables draw `DeltaCell` and have the same mismatch.
- **Mention column width.** The plan said to widen the column to its maximum (200 px) if the change clipped. The fixed table gives the column 152 px whatever it asks for, so nothing was widened. The widest case, "100% avg of 2 +13.4 pts", is 139 px with a `gap-1` and no wrapping in a 140 px content box, about 1 px to spare.
- **Helper names.** The plan's `averageChange` and `stripChange` helpers are `averageChangeOf` and `stripChangeOf` in `lib/compare/change-model.ts`, with `engineChangeOf`, `deltaInput` and the exported `RateChangeInput`. The words-and-change pair `averageChange` lives in `features/prompts/compare/average-change.ts`.
- **New small parts.** `TippedChange` (the tab stop that holds the tooltip of a drawer card or a prompt meta line, only where a tip exists), `DetectableEmpty` (the empty state of the chip), and `ChangeInline` wrapped in a `relative inline-flex` box. Without the box the spoken text of the `Delta`, positioned absolutely, widened the page to 405 px at 390 px.
- **The chip and its reads.** While the held read has not been compared yet (compare just turned on), and after a failed read, the chip leaves the rows alone, so a toggle does not empty the table for a moment. The empty state also tells "the previous period has no answers" (`previous_answers` 0) and "no row has enough answers in both periods" (`tooFewReason`, not in section 5). With a search active the generic filtered state shows.
- **Edits in WP-20 files, outside the leases table.** `topic-drawer/engine-panel.tsx` (the `compare` guard, so the held rows show no change at once when comparison is off) and `topic-drawer/engine-filter.tsx` (the change of the chosen metric on the chosen engine, not the Mention average that D11 named).
